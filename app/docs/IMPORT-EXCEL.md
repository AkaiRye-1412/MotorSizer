# 电机参数 Excel 中间稿方案

## 1. 背景

从 PDF / 图片识别电机参数受多方面影响：Windows OCR 语言包、PowerShell 执行策略、表格线还原、
单位与上下标识别等。识别结果直接入库存在录入错误数据的风险。

改为**两段式**：识别只负责产出候选数据，落到固定模板的 Excel 草稿；人工核对、补全后再由程序
读回入库。

```
PDF / 图片 → OCR 识别 → 导出 Excel 草稿 → 人工校对 → 导入 Excel → 入库
```

## 2. 目标与非目标

**目标**

- 识别预览中的勾选候选可导出为固定模板 `.xlsx`
- 支持从 `.xlsx` 导入电机参数：行级校验、预览、确认后写入数据库
- 同型号覆盖，保留手工维护的私有列（线圈重量等）

**非目标**

- 不再支持把识别结果直接提交入库
- 不改变选型算法、数据库表结构与现有电机字段
- 不改变 OCR / PDF 解析链路本身

## 3. Excel 模板规范

- 工作表名：`电机参数`
- 第 1 行为表头；按**表头名**匹配列，列顺序可变，多余列忽略
- 空单元格按 `0` 处理；数值必须是纯数字，带单位文字（如 `50 N`）判为格式错误
- 直线与旋转共用一份模板，由「类型」列区分

| 列名 | 单位（直线 / 旋转） | 必填 | 说明 |
| --- | --- | --- | --- |
| 型号 | — | 是 | 非空；导入时按名称覆盖同名记录 |
| 类型 | — | 是 | `直线` / `旋转`，兼容 `L` / `R` |
| 冷却方式 | — | 否 | `普通冷却` / `水冷`，空值按普通冷却 |
| 持续值 | N / N·m | 是 | 必须 > 0 |
| 峰值 | N / N·m | 是 | 必须 > 0 |
| 电机常数 | N/√W / N·m/√W | 否 | |
| 力/转矩常数 | N/Arms / N·m/Arms | 否 | |
| 反电动势常数 | V/(m/s) / V/(rad/s) | 否 | |
| 持续电流 | Arms | 否 | |
| 峰值电流 | Arms | 否 | |
| 电感 | mH | 否 | |
| 电阻 | Ω | 否 | |
| 持续功率 | W | 否 | |
| 峰值功率 | W | 否 | |
| 动子质量 / 转子惯量 | kg / kg·m² | 否 | 按「类型」解释单位 |
| 长度 | mm | 否 | |
| 最高速度 / 最高转速 | m/s / rpm | 否 | |
| 来源页码 | — | 否 | 仅作追溯，导入时忽略 |

结构分类（无铁芯 / 有铁芯 / 音圈）由程序按型号自动推断，不放进模板。

## 4. 校验规则

**行级**

- 型号非空
- 类型可识别
- 持续值、峰值必须为正数
- 其余数值必须为非负有限数

**文件级**

- 必需列缺失（型号、类型、持续值、峰值）→ 整份文件报错
- 文件内出现重复型号 → 判为错误（避免导入顺序歧义）
- 有效数据行数为 0 → 报错

**提交策略**：只要存在任何一行或文件级错误，整份 Excel 都不允许提交；预览页逐行列明原因。
错误修复后重新选择文件即可。

## 5. 覆盖规则

沿用 `repo::upsert_motors`：

- 同型号记录以 Excel 中的参数覆盖
- 线圈重量等私有列保持数据库原值

## 6. 模块设计

### 6.1 新增 `src/import/excel.rs`

```rust
/// 模板表头与列映射常量
pub const SHEET_NAME: &str = "电机参数";

/// 草稿行：识别得到的电机与来源页码
pub struct DraftRow {
    pub page: u32,
    pub motor: Motor,
}

/// 把勾选的识别结果写成草稿工作簿
pub fn write_draft(path: &Path, rows: &[DraftRow]) -> Result<(), String>;

/// 读取并校验工作簿；行级错误随行返回
pub fn read_workbook(path: &Path, existing: &[Motor]) -> Result<ExcelPreview, String>;

pub struct ExcelPreview {
    pub path: PathBuf,
    pub rows: Vec<ExcelRow>,
    /// 文件级错误（缺列、重复型号等），任一存在则不可提交
    pub errors: Vec<String>,
    /// 数据库中同名的已有记录，用于预览中标注“覆盖”
    pub existing: Vec<Motor>,
}

pub struct ExcelRow {
    pub line: u32,
    pub name: String,
    /// 校验失败的行为 None
    pub motor: Option<Motor>,
    pub errors: Vec<String>,
}
```

冷却方式的优先级：表格里显式填写时以表格为准；留空时，直线电机按型号家族推断（与既有 `classify` 规则一致），旋转电机按普通冷却。

### 6.2 `src/app/state.rs`

- `ImportPhase` 新增 `ExcelPreview(ExcelPreview)`
- `AppState::select_import_document`：扩展名 `.xlsx` 时跳过页码范围，直接解析
- 新增 `commit_excel_import()`：校验通过后调用 `repo::upsert_motors(&repo::default_db_path(), ...)`
  并 `reload_from_db()`

### 6.3 `src/ui/import_dialog.rs`

- Ready 页：文件类型扩展为 PDF / 图片 / `.xlsx`
- 识别预览页：把「提交导入」替换为「导出 Excel」（导出勾选行）
- 新增 Excel 预览页：表格列出 `行号 / 型号 / 类型 / 持续 / 峰值 / 状态（新增·覆盖·错误）`；
  有错误时提交按钮禁用，显示错误明细，并提供「重新选择文件」按钮

### 6.4 `src/ui/file_dialog.rs`

- 打开对话框增加 `.xlsx` 过滤
- 导出 Excel 使用保存对话框（沿用报告导出的保存逻辑）

## 6.5 识别失败兜底

识别没有产出候选（版式超出解析范围、扫描质量差）时，预览页与失败页都提供
「导出空白模板」：生成只含表头的 `.xlsx`，人工对照样册填写后走同一套导入流程。

同时，识别链路按「文本层优先 + 锚点重建」改造：

- 有文本层的页面优先用 PDF 文本层建表，OCR 只作为兜底；
- 表格结构不再靠“猜表头”，而是由字段标签行（行锚点）与参考行的数值列（列锚点）确定；
- 列标题按列锚点最近的型号文本组成，支持两级表头（型号 + `-V107` 后缀）与串联/并联子表头；
- PDF 文本层按规范推进 text matrix / line matrix，修正表头坐标漂移导致的型号名串列；
- 行标签允许开头 1 个字符的 OCR 误识（如「电机常数」被识别成「电枧常数」）；
- OCR 某页返回空结果时，表格结构回退到该页的 PDF 文本层。

## 7. 依赖与打包

- 写入：`rust_xlsxwriter`
- 读取：`calamine`
- 均为纯 Rust 库，不引入运行时依赖，不影响免安装分发
- 会小幅增加编译时间与 exe 体积

## 8. 测试计划

- 模板写出 → 读回，字段与单位映射一致
- 必填缺失、非法数值、未知类型分别报错
- 文件内重复型号报错
- 同名覆盖保留私有列
- 导出仅包含勾选行

## 9. 风险

- 用户破坏表头：按表头名匹配，缺必需列直接报错并提示列名
- 公式或文本型数字：只接受数值或可解析的数字文本
- 多工作表：优先读取名为 `电机参数` 的工作表，否则取第一个

## 10. 待确认项
